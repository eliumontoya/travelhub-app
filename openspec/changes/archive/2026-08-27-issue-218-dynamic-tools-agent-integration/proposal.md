# Proposal: issue #218 — Dynamic TravelHub tools in WhatsApp inbound agent

## Summary
Wire the controlled TravelHub client tools from PR #216 into the WhatsApp inbound automation pipeline so dynamic customer trip questions can be answered safely or escalated based on structured tool outcomes.

## Scope
- Add dynamic tool result support to the inbound agent/provider contracts.
- Add a server-side dynamic tool execution step in inbound orchestration.
- Resolve client by inbound WhatsApp phone before any trip-specific lookup.
- Execute only allowlisted tools from `runTravelHubClientTool`.
- Handle `success`, `ambiguous`, `not_found`, `blocked`, `error`, and `needs_human` safely.
- Update provider prompt to explain dynamic tool context and citation requirements.
- Persist tool evidence in intent entities and CRM event payloads.
- Add unit tests for dynamic inbound flows.

## Out of scope
- Giving the LLM a general tool-calling API or Supabase credentials.
- SQL generated by the LLM.
- New payment auto-answer policy.
- UI for managing dynamic tool calls.

## Success criteria
- A customer with one active trip can receive a safe summary from WhatsApp.
- Multiple active trips ask for clarification instead of guessing.
- Unknown phone, blocked ownership, payment, and tool errors escalate safely.
- Tests cover the expected result statuses and duplicate idempotency remains intact.
